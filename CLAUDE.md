# Полигон-7 — памятка для Claude Code

Браузерный 3D-шутер от первого лица «Полигон-7». Автор — Кирилл (он не программист-профи, описывает задачи по-русски, разговорно, с опечатками — понимай по смыслу). Игра выкладывается на GitHub Pages из этого репозитория.

## Как работать с Кириллом
- Отвечай **по-русски**, коротко: что изменилось, что проверить. Без длинных технических отчётов.
- Он сам проверяет игру в браузере и пишет, что не так. Делай изменения сразу, не спрашивай лишнего.
- Каждая итерация = новая «версия N». Последняя сделанная — **Version 71** (NET_VER `p7-coop-46`).
- Правь `index.html` в репозитории. **Пока Кирилл коммитит сам**: готовую игру (`index.html`) и обновлённый `CLAUDE.md` отправляй ему файлами в чат, в git не коммить, пока он не попросит.

## Устройство проекта
- **Весь проект — один файл `index.html`** (~14 000 строк, ~2 МБ): HTML + CSS + один большой `<script>` (всё внутри одной IIFE `(() => { ... })();`). Сборки нет, зависимостей нет — всё с CDN:
  - three.js **r128** (cdnjs) — не обновлять, API r128;
  - PeerJS 1.5.4 (jsdelivr) — мультиплеер P2P, грузится по требованию;
  - Firebase compat 12.19.0 (Auth + Realtime Database) — аккаунты, облачное сохранение, таблица лидеров, грузится по требованию.
- Файл огромный: **не читай целиком**. Ищи через grep по именам функций/строк и правь точечно (Edit с уникальным контекстом). Строки очень длинные — многие функции записаны в одну строку.
- Проверка синтаксиса после правок: вытащить содержимое `<script>` и прогнать `node --check` (или `new Function(code)`).

## Главные системы (имена для grep)
- **Режимы**: `mode` = `waves` (волны), `descent` (спуск по подземельям), `roofs`, `pvp`, `tutorial`. Карты — `MAPS`, `buildMap`, `MAP_ORDER`, `DEPTHS`.
- **Игрок/оружие**: `player`, `updatePlayer`, `WEAPONS` (+ `WI` индекс по ключу), `wstate`, `equip`, `SHIELDS`, `SPELLS`, `PETS`, `UPGRADES`, цены апгрейдов `wupCost`, `UP_COST`.
- **Сохранение**: `save` в localStorage `'poligon7-save'` (`SAVE_KEY`), настройки `'poligon7-settings'`, `persist()`. Загрузчик сохранения проверяет каждое поле (`dtherm: s.dtherm && typeof ... ? ... : {}` и т.п.) — **новое поле save нужно добавить в загрузчик**, иначе оно пропадёт. Загрузчик выполняется в самом начале скрипта — константы, объявленные ниже (например `LOOK_OPTS`), в нём использовать нельзя.
- **Аккаунты/облако (Firebase)**: `FB_CFG`, `ACC`, `loadAuth`, `accApply`, `accUpload`, профиль `renderProfile`, аватарки `avaSvg`/`avaHTML`, рамки `frameSvg`. Пути RTDB: `users/$uid` (сохранение), `lb/$uid` (лидерборд), `rooms` (комнаты).
- **Уровни/XP**: `lvInfo`, `addXp`, `LV_MAX = 1000`, звания `LV_RANKS`, награды за каждые 10 уровней до 100 (камуфляжи/аватары/рамки, `DCAMO[k].lvl`). XP за бой: PvE `kills*2 + bossKills*60 + score/300`, PvP `k*60 + 400 (победа) / 120 (участие)`.
- **Мультиплеер**: хост-авторитарный P2P через PeerJS. `NET`, `MATES`, `netSend`, `netTick`, аватары других игроков `o.av.rig`. Константа **`NET_VER`** — **повышай её (`p7-coop-47`, …) только если меняется сетевой протокол** (формат сообщений/синхронизации); если изменения только локальные/визуальные — не трогай, чтобы люди на старой версии могли играть вместе.
- **PvP**: `PVP`, `PVPC` (настройки комнаты: `br` — разрушаемость, `dr` — дредноуты, `dmap` city/port), `pvpStart`, `pvpRespawn`.
- **Дредноуты** (большие мехи в PvP): `DRD` (состояние), `DTYPES` (5 стандартных: Страж, Инферно, Призрак, Горнило, Бастион), свои сборки `dcList()`/`save.dcus` (sid ≥ 11), модули `DMS`, покупка модулей `dmodPrice`/`dmodOwned`, арсенал `renderArsDread`, покраска `dPaint`/`dSetPaint` (поля `a`, `b`, `g` — цвета, `p` — камуфляж, `k` — комплект, `e`, `n`), комплекты `DKIT`, тепловизор `thermToggle`/`thUseC` (обычный 1500, цветной 4500). **У 5 стандартных дредноутов скинов/покраски нет — только у своих сборок.**
- **Карта «Город»** (500×500 м, для дредноутов): `buildCity`, `ensureDCity`, `MAPS.dcity`. **Десантная капсула**: `PODS`, `POD`, `podStart`, `podsUpdate` (открывается на 4 стороны).
- **Разрушаемость**: `destr` (записи `{ms, col, hp, dead, …}`), `hitBrk`, `destroyBrk`, `reviveBrk` (в PvP объекты восстанавливаются ~через минуту), `splitBrk`/`decoSplit` (здания ломаются кусками вместе с подоконниками/балконами), пропсы `PROPC`/`cityProps` (машины взрываются, фонари/деревья ломаются, дредноут давит).
- **Графика**: пост-обработка `POST` (шейдер comp, в т.ч. тепловизор `thm/thg`), камера фона меню `menuCamSafe`.
- **Боец (персонаж игрока)**: `buildRobot(L)` → `humanRobot(...)` (гуманоидное тело). Враги используют `humanoid(...)` — это другая функция, не путать. Анимация: `bendLimbs`, структура рига одинакова (`legL/kneeL/footL`, `torso`, `head`, `armL/foreL` …) — на неё завязаны анимации, оружие (`armAttach`), шлемы и сетевые аватары. Телосложения `HBUILDS`. Опции внешности: `LOOK_OPTS`, `LOOK0`, комплекты `SKIN_SETS`, камуфляжи `DCAMO`/`DPAT`.
- **Снаряжение бойца**: `fighterGear(r, L, bodyMat, glow, dark, vt)` — группы `HEAD`, `MASK`, `SH` (плечи), `BACK`, `HAND`; ключи = значения `LOOK_OPTS`. `vt` — толщина бронежилета (плащи, ранцы и меховой воротник отодвигаются на неё).
- **Бронежилеты**: `VESTS`, `addVest`, владение `vestOwned`/`save.vests`, цвет `look.vcol`, камуфляж `look.vcam`, превью `vestPreview`.
- **Комплекты бойца**: `wearSet` / `unwearSet`, ключи `SET_KEYS`, исходный вид до комплекта — `save.lookPre`, починка несуществующих деталей `lookFix`.
- **UI выбора скинов**: плитки `skTile`, группы `camoGroups`, превью деталей бойца `lookPrevImg`/`lookShot` (рендер в текстуру, очередь), вкладки бойца `charTab` (`skins`, `colors`, `face`, `body`, `gear`), в арсенале дредноута подвкладки `arsPSub` (Скины/Покраска). Esc закрывает любой раздел/оверлей.
- **Магазин/Арсенал**: `renderShop`, `renderArsenal`, вкладки магазина (Скины → комплекты бойца, бронежилеты, скины дредноутов, комплекты дредноутов, камуфляжи).

## Переводы (обязательно)
- Исходный текст интерфейса — **на русском прямо в коде**. Переводы — два словаря в файле: `const I18N_EN = {...}` и `const I18N_DE = {...}` (одной строкой JSON), ключ = **точная русская строка**, значение = перевод. Применяются во время работы (`I18N`, `tr`, `MutationObserver` подменяет текст в DOM).
- **Каждую новую или изменённую русскую строку добавляй в оба словаря** (английский и немецкий). Если меняешь русский текст — старый ключ перестаёт работать, нужен новый.
- Для строк, собираемых из кусков (`«${name}» куплен …`), переводится каждый статичный кусок отдельно.

## Как проверять
- Быстро: синтаксис скрипта (`node --check`).
- Полноценно — Playwright + headless Chromium (`/opt/pw-browsers`, флаги `--use-gl=swiftshader --enable-unsafe-swiftshader`). Весь код внутри IIFE, поэтому в **копию** файла перед последним `})();` вставляется тестовый хук `window.__p7 = s => eval(s);` — через него можно звать `buildRobot`, `wearSet`, рендерить бойца в картинку и т.п. В сам `index.html` хук **не попадает** — `grep -c __p7 index.html` должен быть 0. Тесты и картинки держи в отдельной папке (scratchpad), не коммить мусор в корень.
- В облачной среде CDN (cdnjs/jsdelivr/unpkg) может быть закрыт — three.js r128 берётся из npm (`npm pack three@0.128.0`) и подставляется через `page.route`.
- Для сетевых тестов нужен локальный PeerJS-сервер; `window.P7_PEER = {host, port, path}` переопределяет сервер.

## История версий
- **60–62**: аккаунты (гость или вход), профиль с аватаркой и ачивками, облачное сохранение Firebase; вкладка магазина «Скины»; уровни; при создании комнаты сразу страница «Играть».
- **63**: максимум 1000 уровней, полоска опыта после боя, звания, рамки и аватарки за уровни, таблица лидеров, уровень/аватар в таблице по Tab.
- **64–65**: оружие и апгрейды дороже, XP в PvE меньше; модули дредноутов покупаются (от ~5 000); награды-камуфляжи за уровни (отдельно для бойца и дредноута); структурированные списки камуфляжей; карта «Город» для дредноутов; десантная капсула.
- **66**: разрушение зданий кусками с декором, разрушаемые машины/объекты, камера фона не лезет в дома, тепловизор ярче ночью, цветной тепловизор, хамелеон невидим в тепловизоре, капсула открывается на 4 стороны.
- **67**: выбор обычного/цветного тепловизора, кнопка «Выбрать для битвы» в стиле остальных, новый выбор скинов плитками (вкладки «Скины | Покраска», прокрутка внутри блока) для дредноута и бойца.
- **68**: стандартным дредноутам убраны скины/покраска; Esc выходит из любого раздела; боец стал гуманоидным (`humanRobot`); все настройки бойца (лицо, голова, маска, телосложение, рост, эмблема, плечи, спина, в руках) — плитками с 3D-превью.
- **69**: бронежилеты для бойца (`VESTS`, `addVest`, покупка в Магазине → Скины, цвет или камуфляж); кнопка снятия комплекта (`unwearSet`).
- **70** (детализация бойца, файл от Claude; параллельная версия от Codex `poligon7-v70.html` не объединялась):
  - голова: форма, затылок, уши, нос; `faceTexture` рисует стандартные лица на прозрачном фоне (своя картинка — непрозрачная);
  - всё снаряжение вынесено в `fighterGear`; переработаны все шлемы, маски, наплечники, спина и предметы в руках;
  - кэши и помощники геометрии: `GGEO`/`gg`, `GMAT`/`gmat`, `torG`, `capG`, `latheG`, `extG`, `tubeG`, `clothG` (ткань со складками), `furG` (меховое кольцо), `gearTex`/`gearTexMat`; `rboxG`/`taperG` получили параметр скругления `rf`;
  - `lookShot(L, view, SZ = 150)` — размер превью, ракурс `hands`.
- **71**:
  - бронежилет стал цельным: грудь и живот — одна оболочка по форме корпуса с общей плоской передней стороной (раньше пластины висели отдельно от нижней части); плиты спереди/сзади, лямки, боковые ремни; эмблема выносится поверх плиты (`addVest` возвращает толщину для отступа);
  - цвет бронежилета по умолчанию — чёрный `0x1c1e22` (первый в `LOOK_OPTS.vcol`); старый автоматический оливковый `0x4a5238` при загрузке и у других игроков заменяется на чёрный, оливковый в палитре теперь `0x4b5339`;
  - меховые воротники (Викинг `fur`, Волк `pelt`) — помощник `collar` внутри `fighterGear`: накидка лежит на плечах и кольцо облегает шею, не проходя сквозь неё; `furG(k, Rx, Rz, r, sq, droop)` — эллиптическое кольцо со свисающим внешним краем;
  - смена комплекта: `wearSet` одевает комплект поверх вида «до комплектов» (`save.lookPre`), детали чужих комплектов сбрасываются, камуфляж корпуса (`look.cam`) снимается и возвращается через `unwearSet`; у дредноута выбор комплекта в `dSetPaint` снимает камуфляж (`p = 0`);
  - убран комплект «Тигр» со всеми деталями и попугай у Пирата; несуществующие детали в сохранении чинит `lookFix` (вызывается в `applyLook`). Деньги за купленного «Тигра» не возвращались;
  - исправлен кэш `clothG` (ключ учитывает размеры — плащ правильной ширины для любого телосложения).

## Осторожно
- Не ломай синхронизацию персонажей онлайн: внешность передаётся как объект `look` и строится у всех через `buildRobot`. Удалённые детали у игроков на старых версиях просто не рисуются (`(HEAD[L.head] || noop)()`).
- Имена в файле легко пересекаются (было: `tpG` уже занято) — перед добавлением новой глобальной функции/константы проверь grep'ом, что имя свободно.
- Кэши геометрии (`gg`) хранят по ключу — **в ключ должны входить все размеры**, иначе разные телосложения получат одну и ту же геометрию.
- Firebase-конфиг (`apiKey` и т.п.) в клиенте — это нормально, безопасность держится на правилах RTDB (каждый пишет только в свои `users/$uid` и `lb/$uid`).
