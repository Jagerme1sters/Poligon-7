# Полигон-7 — памятка для Claude Code

Браузерный 3D-шутер от первого лица «Полигон-7». Автор — Кирилл (он не программист-профи, описывает задачи по-русски, разговорно, с опечатками — понимай по смыслу). Игра выкладывается на GitHub Pages из этого репозитория.

## Как работать с Кириллом

* Отвечай **по-русски**, коротко: что изменилось, что проверить. Без длинных технических отчётов.
* Он сам проверяет игру в браузере и пишет, что не так. Делай изменения сразу, не спрашивай лишнего.
* Каждая итерация = новая «версия N». Последняя сделанная до перехода в Claude Code — **Version 68** (NET\_VER `p7-coop-46`).
* Раньше файл назывался `poligon7.html` и Кирилл сам заливал его как `index.html`. Теперь правь `index.html` в репозитории напрямую и коммить.

## Устройство проекта

* **Весь проект — один файл `index.html`** (\~14 000 строк, \~1,8 МБ): HTML + CSS + один большой `<script>`. Сборки нет, зависимостей нет — всё с CDN:

  * three.js **r128** (cdnjs) — не обновлять, API r128;
  * PeerJS 1.5.4 (jsdelivr) — мультиплеер P2P;
  * Firebase compat 12.19.0 (Auth + Realtime Database) — аккаунты, облачное сохранение, таблица лидеров.
* Файл огромный: **не читай целиком**. Ищи через grep по именам функций/строк и правь точечно (Edit с уникальным контекстом). Строки очень длинные — многие функции записаны в одну строку.
* Проверка синтаксиса после правок: вытащить содержимое `<script>` и прогнать `node --check` (или `new Function(code)`).

## Главные системы (имена для grep)

* **Режимы**: `mode` = `waves` (волны), `descent` (спуск по подземельям), `roofs`, `pvp`, `tutorial`. Карты — `MAPS`, `buildMap`, `MAP\\\_ORDER`, `DEPTHS`.
* **Игрок/оружие**: `player`, `updatePlayer`, `WEAPONS` (+ `WI` индекс по ключу), `wstate`, `equip`, `SHIELDS`, `SPELLS`, `PETS`, `UPGRADES`, цены апгрейдов `wupCost`, `UP\\\_COST`.
* **Сохранение**: `save` в localStorage `'poligon7-save'` (`SAVE\\\_KEY`), настройки `'poligon7-settings'`, `persist()`. Загрузчик сохранения проверяет каждое поле (`dtherm: s.dtherm \\\&\\\& typeof ... ? ... : {}` и т.п.) — **новое поле save нужно добавить в загрузчик**, иначе оно пропадёт.
* **Аккаунты/облако (Firebase)**: `FB\\\_CFG`, `ACC`, `loadAuth`, `accApply`, `accUpload`, профиль `renderProfile`, аватарки `avaSvg`/`avaHTML`, рамки `frameSvg`. Пути RTDB: `users/$uid` (сохранение), `lb/$uid` (лидерборд), `rooms` (комнаты).
* **Уровни/XP**: `lvInfo`, `addXp`, `LV\\\_MAX = 1000`, звания `LV\\\_RANKS`, награды за каждые 10 уровней до 100 (камуфляжи/аватары/рамки, `DCAMO\\\[k].lvl`). XP за бой: PvE `kills\\\*2 + bossKills\\\*60 + score/300`, PvP `k\\\*60 + 400 (победа) / 120 (участие)`.
* **Мультиплеер**: хост-авторитарный P2P через PeerJS. `NET`, `MATES`, `netSend`, `netTick`, аватары других игроков `o.av.rig`. Константа **`NET\\\_VER`** — **повышай её (`p7-coop-47`, …) только если меняется сетевой протокол** (формат сообщений/синхронизации); если изменения только локальные/визуальные — не трогай, чтобы люди на старой версии могли играть вместе.
* **PvP**: `PVP`, `PVPC` (настройки комнаты: `br` — разрушаемость, `dr` — дредноуты, `dmap` city/port), `pvpStart`, `pvpRespawn`.
* **Дредноуты** (большие мехи в PvP): `DRD` (состояние), `DTYPES` (5 стандартных: Страж, Инферно, Призрак, Горнило, Бастион), свои сборки `dcList()`/`save.dcus` (sid ≥ 11), модули `DMS`, покупка модулей `dmodPrice`/`dmodOwned`, арсенал `renderArsDread`, покраска `dPaint`/`dSetPaint`, комплекты `DKIT`, тепловизор `thermToggle`/`thUseC` (обычный 1500, цветной 4500). **У 5 стандартных дредноутов скинов/покраски нет — только у своих сборок.**
* **Карта «Город»** (500×500 м, для дредноутов): `buildCity`, `ensureDCity`, `MAPS.dcity`. **Десантная капсула**: `PODS`, `POD`, `podStart`, `podsUpdate` (открывается на 4 стороны).
* **Разрушаемость**: `destr` (записи `{ms, col, hp, dead, …}`), `hitBrk`, `destroyBrk`, `reviveBrk` (в PvP объекты восстанавливаются \~через минуту), `splitBrk`/`decoSplit` (здания ломаются кусками вместе с подоконниками/балконами), пропсы `PROPC`/`cityProps` (машины взрываются, фонари/деревья ломаются, дредноут давит).
* **Графика**: пост-обработка `POST` (шейдер comp, в т.ч. тепловизор `thm/thg`), камера фона меню `menuCamSafe`.
* **Боец (персонаж игрока)**: `buildRobot(L)` → `humanRobot(...)` (гуманоидное тело, Version 68). Враги используют `humanoid(...)` — это другая функция, не путать. Анимация: `bendLimbs`, структура рига одинакова (`legL/kneeL/footL`, `torso`, `head`, `armL/foreL` …) — на неё завязаны анимации, оружие (`armAttach`), шлемы и сетевые аватары. Опции внешности: `LOOK\\\_OPTS`, `LOOK0`, комплекты `SKIN\\\_SETS`, камуфляжи `DCAMO`/`DPAT`.
* **UI выбора скинов**: плитки `skTile`, группы `camoGroups`, превью деталей бойца `lookPrevImg`/`lookShot` (рендер в текстуру, очередь), вкладки бойца `charTab` (`skins`, `colors`, `face`, `body`, `gear`), в арсенале дредноута подвкладки `arsPSub` (Скины/Покраска). Esc закрывает любой раздел/оверлей.
* **Магазин/Арсенал**: `renderShop`, `renderArsenal`, вкладки магазина (Скины → комплекты бойца, скины дредноутов, комплекты дредноутов, камуфляжи).

## Переводы (обязательно)

* Исходный текст интерфейса — **на русском прямо в коде**. Переводы — два словаря в файле: `const I18N\\\_EN = {...}` и `const I18N\\\_DE = {...}` (одной строкой JSON), ключ = **точная русская строка**, значение = перевод. Применяются во время работы (`I18N`, `tr`, `MutationObserver` подменяет текст в DOM).
* **Каждую новую или изменённую русскую строку добавляй в оба словаря** (английский и немецкий). Если меняешь русский текст — старый ключ перестаёт работать, нужен новый.
* Для строк, собираемых из кусков (`«${name}» куплен …`), переводится каждый статичный кусок отдельно.

## Как проверять

* Быстро: синтаксис скрипта (`node --check`).
* Полноценно раньше делалось через Playwright + headless Chromium (swiftshader), с заглушкой `requestAnimationFrame` и тестовым хуком `window.\\\_\\\_p7`, который вставлялся в копию файла (в сам `index.html` хук **не попадает** — `grep -c \\\_\\\_p7 index.html` должен быть 0). Если будешь писать тесты — делай это в отдельной папке и не коммить мусор в корень.
* Для сетевых тестов нужен локальный PeerJS-сервер; `window.P7\\\_PEER = {host, port, path}` переопределяет сервер.

## История последних версий

* **60–62**: аккаунты (гость или вход), профиль с аватаркой и ачивками, облачное сохранение Firebase; вкладка магазина «Скины»; уровни; при создании комнаты сразу страница «Играть».
* **63**: максимум 1000 уровней, полоска опыта после боя, звания, рамки и аватарки за уровни, таблица лидеров, уровень/аватар в таблице по Tab.
* **64–65**: оружие и апгрейды дороже, XP в PvE меньше; модули дредноутов покупаются (от \~5 000); награды-камуфляжи за уровни (отдельно для бойца и дредноута); структурированные списки камуфляжей; карта «Город» для дредноутов; десантная капсула.
* **66**: разрушение зданий кусками с декором, разрушаемые машины/объекты, камера фона не лезет в дома, тепловизор ярче ночью, цветной тепловизор, хамелеон невидим в тепловизоре, капсула открывается на 4 стороны.
* **67**: выбор обычного/цветного тепловизора, кнопка «Выбрать для битвы» в стиле остальных, новый выбор скинов плитками (вкладки «Скины | Покраска», прокрутка внутри блока) для дредноута и бойца.
* **68**: стандартным дредноутам убраны скины/покраска; Esc выходит из любого раздела; боец стал гуманоидным (`humanRobot`); все настройки бойца (лицо, голова, маска, телосложение, рост, эмблема, плечи, спина, в руках) — плитками с 3D-превью.

## Осторожно

* Не ломай синхронизацию персонажей онлайн: внешность передаётся как объект `look` и строится у всех через `buildRobot`.
* Имена в файле легко пересекаются (было: `tpG` уже занято) — перед добавлением новой глобальной функции/константы проверь grep'ом, что имя свободно.
* Firebase-конфиг (`apiKey` и т.п.) в клиенте — это нормально, безопасность держится на правилах RTDB (каждый пишет только в свои `users/$uid` и `lb/$uid`).

## Version 70

Детализация бойца (30.09.2026). Проверено по файлу `poligon7 (4).html` от Claude. Это продолжение версии Claude, отдельное от `poligon7-v70.html`, сделанного Codex: изменения этих файлов пока не объединены.

### Что изменилось

* **Голова и лицо**: в `humanRobot` изменена форма головы, добавлены объём затылка и небольшие уши; в `buildRobot` добавлен нос (кроме своей картинки и некоторых масок). `faceTexture` теперь рисует стандартные лица на прозрачном фоне, а не на сплошном тёмном прямоугольнике. Для загруженной картинки фон остаётся непрозрачным. Превью лиц в `lookPrevImg` учитывает цвет корпуса.
* **Снаряжение бойца**: построение головных уборов, масок, наплечников, предметов на спине и в руках вынесено из `buildRobot` в новую функцию `fighterGear(r, L, bodyMat, glow, dark, vt)`. Внутри неё группы `HEAD`, `MASK`, `SH`, `BACK`, `HAND`; ключи соответствуют прежним значениям `LOOK_OPTS`. Для добавления или правки детали ищи нужную группу.
* **Шлемы и маски**: переработаны все существующие варианты. У спартанца — округлый шлем, защита щёк и носа, фигурный гребень; у викинга — изогнутые рога; у самурая — детали кабуто. Переработаны борода, щупальца, клыки, звериные морды и остальные аксессуары.
* **Плечи и спина**: наплечники подогнаны под размеры плеч; плащи и флаги получили складки и изгиб поверхности. Переработаны меховые воротники, попугай, реактивный ранец, крылья, плавники и хвосты. Это геометрия складок, не физическая симуляция ткани.
* **Предметы в руках**: переработаны бластер, мечи, щиты, копьё, секира, катана, сабля, трезубец, дубина и когти. Точки крепления рассчитываются по размерам рук `r.Ar`; внутри `fighterGear` используются помощники `R` и `Lf`.

### Новые функции и кэши (имена для поиска)

* `GGEO` / `gg` — кэш геометрии; `GMAT` / `gmat` — кэш материалов и текстур снаряжения.
* `torG` — торы; `capG` — сферические купола; `latheG` — поверхности вращения; `extG` — объёмные детали по плоскому контуру; `tubeG` — изогнутые трубки с меняющимся радиусом; `clothG` — ткань со складками; `furG` — меховой воротник.
* `gearTex` — процедурные текстуры; `gearTexMat` — материалы деревянных досок щита и обмотки рукоятей.
* `rboxG(w, h, d, rf = 0.24)` и `taperG(wT, wB, h, dT, dB, flatFront, rf = 0.24)` получили параметр скругления `rf`. Старые вызовы сохраняют прежнее значение по умолчанию.
* `lookShot(L, view, SZ = 150)` позволяет задавать размер картинки превью; добавлен ракурс `hands`. В `LPV_VIEW` выбор предмета в руках пока использует прежний ракурс `full`.

### Совместимость и что проверить

* Поля внешности `look`, покупки, бронежилеты `VESTS` / `addVest` и интерфейс снятия комплекта в этом обновлении не менялись. `NET_VER` остался `p7-coop-46`; формат сетевых сообщений не изменён.
* **Известный недочёт смены комплектов**: `wearSet` по-прежнему накладывает только поля нового комплекта поверх текущего. Проверено: после «Волк → Спартанец» остаются `mask: 'snout'` и `face: 'eyes'`. При исправлении нужно учитывать все слоты комплекта и восстановление внешности через `lookPre` / `unwearSet`.
* **Известный недочёт кэша плащей**: `clothG` кэширует геометрию только по имени `k`, хотя ширина плаща зависит от телосложения. Повторный вызов с другой шириной возвращает первую геометрию. При исправлении включи размеры и параметры формы в ключ кэша; проверь лёгкое, обычное и массивное телосложение.
* Синтаксис скрипта проверен через `node --check`. Два недочёта выше воспроизведены отдельными проверками кода. Полный запуск игры и визуальная проверка этого обновления в браузере не выполнялись.
