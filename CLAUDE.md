# Полигон-7 — памятка для Claude Code

Браузерный 3D-шутер от первого лица «Полигон-7». Автор — Кирилл (он не программист-профи, описывает задачи по-русски, разговорно, с опечатками — понимай по смыслу). Игра выкладывается на GitHub Pages из этого репозитория.

## Как работать с Кириллом
- Отвечай **по-русски**, коротко: что изменилось, что проверить. Без длинных технических отчётов.
- Он сам проверяет игру в браузере и пишет, что не так. Делай изменения сразу, не спрашивай лишнего.
- Каждая итерация = новая «версия N». Последняя сделанная до перехода в Claude Code — **Version 68** (NET_VER `p7-coop-46`).
- Раньше файл назывался `poligon7.html` и Кирилл сам заливал его как `index.html`. Теперь правь `index.html` в репозитории напрямую и коммить.

## Устройство проекта
- **Весь проект — один файл `index.html`** (~14 000 строк, ~1,8 МБ): HTML + CSS + один большой `<script>`. Сборки нет, зависимостей нет — всё с CDN:
  - three.js **r128** (cdnjs) — не обновлять, API r128;
  - PeerJS 1.5.4 (jsdelivr) — мультиплеер P2P;
  - Firebase compat 12.19.0 (Auth + Realtime Database) — аккаунты, облачное сохранение, таблица лидеров.
- Файл огромный: **не читай целиком**. Ищи через grep по именам функций/строк и правь точечно (Edit с уникальным контекстом). Строки очень длинные — многие функции записаны в одну строку.
- Проверка синтаксиса после правок: вытащить содержимое `<script>` и прогнать `node --check` (или `new Function(code)`).

## Главные системы (имена для grep)
- **Режимы**: `mode` = `waves` (волны), `descent` (спуск по подземельям), `roofs`, `pvp`, `tutorial`. Карты — `MAPS`, `buildMap`, `MAP_ORDER`, `DEPTHS`.
- **Игрок/оружие**: `player`, `updatePlayer`, `WEAPONS` (+ `WI` индекс по ключу), `wstate`, `equip`, `SHIELDS`, `SPELLS`, `PETS`, `UPGRADES`, цены апгрейдов `wupCost`, `UP_COST`.
- **Сохранение**: `save` в localStorage `'poligon7-save'` (`SAVE_KEY`), настройки `'poligon7-settings'`, `persist()`. Загрузчик сохранения проверяет каждое поле (`dtherm: s.dtherm && typeof ... ? ... : {}` и т.п.) — **новое поле save нужно добавить в загрузчик**, иначе оно пропадёт.
- **Аккаунты/облако (Firebase)**: `FB_CFG`, `ACC`, `loadAuth`, `accApply`, `accUpload`, профиль `renderProfile`, аватарки `avaSvg`/`avaHTML`, рамки `frameSvg`. Пути RTDB: `users/$uid` (сохранение), `lb/$uid` (лидерборд), `rooms` (комнаты).
- **Уровни/XP**: `lvInfo`, `addXp`, `LV_MAX = 1000`, звания `LV_RANKS`, награды за каждые 10 уровней до 100 (камуфляжи/аватары/рамки, `DCAMO[k].lvl`). XP за бой: PvE `kills*2 + bossKills*60 + score/300`, PvP `k*60 + 400 (победа) / 120 (участие)`.
- **Мультиплеер**: хост-авторитарный P2P через PeerJS. `NET`, `MATES`, `netSend`, `netTick`, аватары других игроков `o.av.rig`. Константа **`NET_VER`** — **повышай её (`p7-coop-47`, …) только если меняется сетевой протокол** (формат сообщений/синхронизации); если изменения только локальные/визуальные — не трогай, чтобы люди на старой версии могли играть вместе.
- **PvP**: `PVP`, `PVPC` (настройки комнаты: `br` — разрушаемость, `dr` — дредноуты, `dmap` city/port), `pvpStart`, `pvpRespawn`.
- **Дредноуты** (большие мехи в PvP): `DRD` (состояние), `DTYPES` (5 стандартных: Страж, Инферно, Призрак, Горнило, Бастион), свои сборки `dcList()`/`save.dcus` (sid ≥ 11), модули `DMS`, покупка модулей `dmodPrice`/`dmodOwned`, арсенал `renderArsDread`, покраска `dPaint`/`dSetPaint`, комплекты `DKIT`, тепловизор `thermToggle`/`thUseC` (обычный 1500, цветной 4500). **У 5 стандартных дредноутов скинов/покраски нет — только у своих сборок.**
- **Карта «Город»** (500×500 м, для дредноутов): `buildCity`, `ensureDCity`, `MAPS.dcity`. **Десантная капсула**: `PODS`, `POD`, `podStart`, `podsUpdate` (открывается на 4 стороны).
- **Разрушаемость**: `destr` (записи `{ms, col, hp, dead, …}`), `hitBrk`, `destroyBrk`, `reviveBrk` (в PvP объекты восстанавливаются ~через минуту), `splitBrk`/`decoSplit` (здания ломаются кусками вместе с подоконниками/балконами), пропсы `PROPC`/`cityProps` (машины взрываются, фонари/деревья ломаются, дредноут давит).
- **Графика**: пост-обработка `POST` (шейдер comp, в т.ч. тепловизор `thm/thg`), камера фона меню `menuCamSafe`.
- **Боец (персонаж игрока)**: `buildRobot(L)` → `humanRobot(...)` (гуманоидное тело, Version 68). Враги используют `humanoid(...)` — это другая функция, не путать. Анимация: `bendLimbs`, структура рига одинакова (`legL/kneeL/footL`, `torso`, `head`, `armL/foreL` …) — на неё завязаны анимации, оружие (`armAttach`), шлемы и сетевые аватары. Опции внешности: `LOOK_OPTS`, `LOOK0`, комплекты `SKIN_SETS`, камуфляжи `DCAMO`/`DPAT`.
- **UI выбора скинов**: плитки `skTile`, группы `camoGroups`, превью деталей бойца `lookPrevImg`/`lookShot` (рендер в текстуру, очередь), вкладки бойца `charTab` (`skins`, `colors`, `face`, `body`, `gear`), в арсенале дредноута подвкладки `arsPSub` (Скины/Покраска). Esc закрывает любой раздел/оверлей.
- **Магазин/Арсенал**: `renderShop`, `renderArsenal`, вкладки магазина (Скины → комплекты бойца, скины дредноутов, комплекты дредноутов, камуфляжи).

## Переводы (обязательно)
- Исходный текст интерфейса — **на русском прямо в коде**. Переводы — два словаря в файле: `const I18N_EN = {...}` и `const I18N_DE = {...}` (одной строкой JSON), ключ = **точная русская строка**, значение = перевод. Применяются во время работы (`I18N`, `tr`, `MutationObserver` подменяет текст в DOM).
- **Каждую новую или изменённую русскую строку добавляй в оба словаря** (английский и немецкий). Если меняешь русский текст — старый ключ перестаёт работать, нужен новый.
- Для строк, собираемых из кусков (`«${name}» куплен …`), переводится каждый статичный кусок отдельно.

## Как проверять
- Быстро: синтаксис скрипта (`node --check`).
- Полноценно раньше делалось через Playwright + headless Chromium (swiftshader), с заглушкой `requestAnimationFrame` и тестовым хуком `window.__p7`, который вставлялся в копию файла (в сам `index.html` хук **не попадает** — `grep -c __p7 index.html` должен быть 0). Если будешь писать тесты — делай это в отдельной папке и не коммить мусор в корень.
- Для сетевых тестов нужен локальный PeerJS-сервер; `window.P7_PEER = {host, port, path}` переопределяет сервер.

## История последних версий
- **60–62**: аккаунты (гость или вход), профиль с аватаркой и ачивками, облачное сохранение Firebase; вкладка магазина «Скины»; уровни; при создании комнаты сразу страница «Играть».
- **63**: максимум 1000 уровней, полоска опыта после боя, звания, рамки и аватарки за уровни, таблица лидеров, уровень/аватар в таблице по Tab.
- **64–65**: оружие и апгрейды дороже, XP в PvE меньше; модули дредноутов покупаются (от ~5 000); награды-камуфляжи за уровни (отдельно для бойца и дредноута); структурированные списки камуфляжей; карта «Город» для дредноутов; десантная капсула.
- **66**: разрушение зданий кусками с декором, разрушаемые машины/объекты, камера фона не лезет в дома, тепловизор ярче ночью, цветной тепловизор, хамелеон невидим в тепловизоре, капсула открывается на 4 стороны.
- **67**: выбор обычного/цветного тепловизора, кнопка «Выбрать для битвы» в стиле остальных, новый выбор скинов плитками (вкладки «Скины | Покраска», прокрутка внутри блока) для дредноута и бойца.
- **68**: стандартным дредноутам убраны скины/покраска; Esc выходит из любого раздела; боец стал гуманоидным (`humanRobot`); все настройки бойца (лицо, голова, маска, телосложение, рост, эмблема, плечи, спина, в руках) — плитками с 3D-превью.

## Осторожно
- Не ломай синхронизацию персонажей онлайн: внешность передаётся как объект `look` и строится у всех через `buildRobot`.
- Имена в файле легко пересекаются (было: `tpG` уже занято) — перед добавлением новой глобальной функции/константы проверь grep'ом, что имя свободно.
- Firebase-конфиг (`apiKey` и т.п.) в клиенте — это нормально, безопасность держится на правилах RTDB (каждый пишет только в свои `users/$uid` и `lb/$uid`).
